## 2026-09-04 11:49
- Milestone 4 (remaining tools): crop, highlighter, blur/pixelate and freehand pen, built in parallel with the milestone 3 agent working on badges and text
- Tools/CropTool.swift: drag a rectangle over the capture, everything outside it dims, eight handles plus rule-of-thirds guides and a live "W x H px" readout let it be adjusted before anything is committed. Drag inside the rectangle to move it, drag a handle to reshape it, and it is clamped to the image so an applied crop is never a different shape than the one on screen. Return, keypad Enter, a double-click inside the rectangle, or the "Apply crop" pill commits through document.setCrop, which is exactly one undo step; Esc drops the in-flight rectangle and leaves the document alone. If a crop already exists the tool starts from it
- Crop is non-destructive as designed: the document keeps the original CGImage and only stores a rect, annotations keep their original pixel coordinates (a test pins that down), and Renderer clips to outputRect so a flattened export comes out at the cropped size. Undo restores the previous rect and therefore the previous output size
- Removing or re-drawing a crop: once a crop is applied the canvas shows only the cropped area, so there is nothing left outside it to drag. Selecting the crop tool therefore sets the new EditorDocument.isSuspendingCropForEditing flag, which makes the CANVAS (never export) show the whole capture again with the current crop dimmed, ready to be re-dragged. A "Reset crop" pill in the overlay clears the crop completely and is the documented way back to the full image; it is a button rather than a Cmd+Shift+R key equivalent because CanvasView.performKeyEquivalent owns the Cmd shortcuts and a menu bar app has no menu to hang another one on. An "Adjust crop" pill re-enters the whole-image view after an apply. Leaving the tool always clears the flag
- Tools/HighlightTool.swift: drag out a highlight rect, drawn by the existing Renderer path (40% alpha, multiply blend, so the text underneath stays readable). Picking the tool switches the shared inspector color to yellow no matter what the shape stroke color was, and leaving the tool puts the old color back unless the color picker was touched in the meantime, in which case the user's choice wins. Selection, move and resize come from SelectTool through the generic rect handling, which a test confirms including all eight handles
- The file also holds RectDragTool, a small sibling of ShapeCreationTool used by the highlighter and the blur tool. ShapeCreationTool takes activate/deactivate from the CanvasTool protocol EXTENSION, and a Swift subclass cannot override a protocol extension member, so a subclass hook for "set yellow when the tool is picked" would never have been called. Writing a base class in a milestone 4 file avoided editing a file the milestone 3 agent might also have been changing
- Tools/BlurTool.swift: drag out a blur rect. The annotation stores nothing but the rect, so the effect follows it when it is moved or resized and vanishes with a delete. The stroke width slider doubles as the strength: block size is strokeWidth * 3, so 1 to 12 covers 3 to 36 pixel blocks and no new inspector control was needed
- Renderer.swift (additive): blur block size raised from max(8, width * 2) to max(3, width * 3) to match that contract, and the CIPixellate pass moved behind a small keyed cache. It already cropped the base image before filtering rather than filtering the whole image, but it re-ran the filter on every redraw, so dragging a blur re-filtered on every mouse-moved event. The cache is keyed on the base image identity, the integral region and the block size, holds 24 entries and is guarded by an NSLock because export can render off the main thread. Also: draw() now takes its rect from document.displayRect, and renderImage() clears isSuspendingCropForEditing for the duration of the render so a flattened image always uses the applied crop
- Verified in a rendered PNG over a real screenshot: the pixellated blocks fill the blur rect exactly (a reference outline was drawn at the same frame), text inside is unreadable, text is untouched right up to the edge, and there is no offset from the flipped context. A test compares every pixel of a striped test image before and after and asserts zero changed pixels outside the rect
- Tools/PenTool.swift: mouse down starts a path, drag appends points, mouse up commits one annotation as one undo step. Points closer than 2 px to the last kept point are dropped (the threshold is converted through the canvas so zooming out does not turn a curve into a polygon), the last sample is always kept so the line ends where the mouse did, and a press that never travels 3 points is treated as a click and discarded. Rendered by the existing Renderer path as a stroked polyline with round caps and joins in the stroke color and width. Selection hit tests along the segments and move works; paths report no resize handles, which is deliberate
- EditorDocument.swift (additive): isSuspendingCropForEditing plus displayRect (outputRect, or the whole image while the crop tool is adjusting an applied crop). No existing signature changed
- CanvasView.swift (additive): layout, view<->document conversion and drawing now read document.displayRect instead of document.outputRect, the two being identical unless the crop tool is adjusting a crop; the observation block tracks the new flag; and updateContentLayout re-fits when the DISPLAYED size changes, not only when the window changes, so applying or clearing a crop refits the canvas instead of keeping the old zoom. The crop tests assert the canvas shows and converts against the cropped area after an apply
- Tests/ToolTests-M4.swift: 17 tests. Crop apply changing Renderer.outputPixelSize and the flattened image size with undo restoring both, annotations keeping their pixel coordinates through a crop, the canvas fitting the cropped rect, the whole-image view while adjusting (with export still cropped), the Reset crop pill and its undo, Esc committing nothing, highlighter yellow default and restore, a pixel check that a highlight leaves a yellow cast over white and nothing outside, highlight selection and move, blur creation, the pixel-level "inside only" check, block size following the stroke width, pen thinning with one annotation and one undo step, a click drawing nothing, path hit testing and move, and a pixel check of the stroke color
- Full suite is 97 tests, all passing; clean build with no warnings
