# ZeroShot

A small, native macOS screenshot tool in the spirit of Greenshot. Press **Cmd+0**, pick a region with Apple's own picker, and an editor window opens where you crop, draw shapes, add text, and drop auto-numbered badges (1, 2, 3...) for documentation. Result goes to the clipboard and a folder.

Status: **milestones 1 to 6 built**, 97 unit tests passing, Debug and Release both build clean. `Scripts/build-release.sh` installs to /Applications and was run once end to end (launch, pgrep, codesign check all passed). Not yet exercised with a real Cmd+0 capture; that needs the Screen Recording permission prompt answered by a person.

## Decisions (locked)

| Topic | Decision | Why |
|---|---|---|
| Stack | Native Swift: SwiftUI chrome + one AppKit canvas view | Smallest app, best OS integration, no web runtime |
| Capture UI | Shell out to `/usr/sbin/screencapture -i` | Apple's crosshair, Space for window mode, Esc to cancel, multi-monitor, all free |
| Editor | Separate editor window (Greenshot style) | Simplest, reliable, easy undo/redo and text entry |
| Hotkey | Cmd+0 (changeable in Preferences) | User choice. Note: overrides "Actual Size" in browsers and editors while ZeroShot runs |
| Output | Clipboard + PNG in default folder; Greenshot-style destination menu for other folders | Paste right away, keep a file for later |
| Tools | Select, Crop, Rectangle, Ellipse (outline only), Arrow, Line, Text, Number badge, Highlighter, Blur/pixelate, Freehand pen | All requested |
| Min macOS | 15.0 | Dev machine is 26.3, Xcode 26.2. 15 keeps modern SwiftUI without excluding older Macs |
| Project gen | XcodeGen (`project.yml`) | Already installed; keeps the .xcodeproj out of hand-editing |
| Bundle id | `us.kindcode.zeroshot` | |
| App type | Menu bar only (`LSUIElement`), no Dock icon | Greenshot-like; stays out of the way |

## User flow

1. App sits in the menu bar. Menu: Capture Region (Cmd+0), Capture Window, Capture Full Screen, Capture with 5s delay, Open Last Screenshot, Preferences, Quit.
2. Cmd+0 runs `screencapture -i -x -t png <tmp.png>`. If the file does not appear, the user pressed Esc: do nothing.
3. Editor window opens with the image. Toolbar across the top, small inspector strip for color, stroke width, font size, badge color.
4. User annotates. Number tool: each click drops the next number (1, 2, 3...). Counter resets for every new capture.
5. **Done** (Cmd+Return): flatten, copy PNG to clipboard, save PNG to default folder, close window.
   **Save to...** dropdown: default folder, any favorite folder, Save As..., Copy only, Open in Preview.
6. Esc or Close asks to discard if there are unsaved edits.

### Coordinate convention (important for every later change)

**Document space == image PIXEL space, origin TOP-LEFT, +y down.**

Every rect and point in `Annotation`, `EditorDocument` and `Renderer` is in that
space. A 2x Retina capture of a 1440x900 point region is a 2880x1800 document,
and nothing in the model knows about points. `Renderer.draw` flips the CGContext
exactly once at the top and then works top-left throughout; images need a local
counter-flip, which `Renderer` handles internally. The canvas view is the only
place allowed to divide by a display scale.

There is no reliable way to recover "points" from a PNG on disk, so
`CaptureService` does not try: it hands back the CGImage plus its exact pixel
size and lets the document own the pixels.

### Language mode

Targets build in **Swift 5 language mode** (`SWIFT_VERSION = 5.0`). Swift 6
strict concurrency fights the AppKit and Carbon APIs this app leans on. UI types
are still annotated `@MainActor` by hand.

### Why one AppKit canvas view instead of pure SwiftUI

Mouse tracking, drag precision, hit testing, and resize handles are much simpler in an `NSView` with `mouseDown/Dragged/Up` than with SwiftUI gestures. SwiftUI still owns everything around it (toolbar, inspector, preferences, menu bar), so the app stays mostly SwiftUI.

### Adding a tool

`CanvasView` knows nothing about individual tools. It resolves the active
`ToolKind` through `ToolRegistry` and forwards mouse and key events to whatever
`CanvasTool` comes back. To add the badge, text, crop, highlighter, blur or pen
tool:

1. create `Sources/Editor/Tools/<Name>Tool.swift` with a class conforming to
   `CanvasTool`,
2. add one `register(.<kind>) { <Name>Tool() }` line to
   `ToolRegistry.registerBuiltInToolsIfNeeded()` in `Tools/Tool.swift`.

Nothing in `CanvasView` or `EditorWindow` changes. Unregistered kinds still show
in the toolbar (dimmed) and resolve to `UnimplementedTool`, which does nothing.

Points handed to a tool are in document space. `draw(overlayIn:canvas:)` paints
in view space; call `canvas.applyDocumentTransform(to:)` plus
`Renderer.drawPreview` to draw a live preview with the real renderer instead of
a look-alike.

Undo policy for tools: one undo step per DRAG. Open a group lazily on the first
real mutation with `document.beginUndoGroup(actionName:)`, pass
`registersUndo: true` for that first mutation and `false` for every later one in
the same drag, then `document.endUndoGroup()` on mouse up. `SelectTool` is the
worked example.

### Annotation model

Value types, stored in an array in draw order. Every mutation replaces the array, and `UndoManager` keeps the previous array. Cheap, correct, and undo/redo comes for free.

Common fields: id, kind, frame or points, stroke color, stroke width, fill, z-order.

Badge specifics: `number: Int`, `color`, `radius` (from size setting). Rendered as a filled circle with a white bold number. Inspector lets you edit the number of a selected badge. A **Renumber** button re-sequences all badges by creation order. Deleting a badge does not shift the others (same as Greenshot), Renumber fixes gaps when wanted.

Ellipse: stroke only, transparent center, as requested. Fill is available as an option but off by default.

Crop: non-destructive. The document keeps the original image plus a crop rect. Rendering and export clip to the crop rect. Undo restores the previous rect.

Blur: `CIPixellate` applied to the base image inside the region at render time. Pixelate, not gaussian, so it is not reversible.

Text: while editing, an `NSTextView` overlay sits on the canvas. On commit it becomes a text annotation drawn by Core Text. Double-click to edit again.

### Capture details

- Region: `screencapture -i -x -t png <tmp>`. Space switches to window mode inside Apple's picker.
- Window: `screencapture -i -W -x -t png <tmp>` (starts in window mode).
- Full screen: `screencapture -x -t png <tmp>` (all displays; pick main display first, multi-display later if wanted).
- Delayed: `-T 5`.
- Cancel detection: no file at the tmp path, a zero-byte file, or a non-zero exit status.
- Temp files live in `$TMPDIR/ZeroShot/capture-<uuid>.png`.
- First run: macOS prompts for Screen Recording permission for ZeroShot. The app must be signed with a stable identity (Development team, or a fixed ad-hoc identity) so rebuilds do not re-prompt every time.

### Hotkey

Carbon `RegisterEventHotKey` for Cmd+0. Works from a menu bar app without Accessibility or Input Monitoring permission. Preferences has a recorder field to change it.

### Export

Flatten at the image's native scale (2x on Retina) so the saved PNG matches what Apple's tool produces. Clipboard gets PNG and TIFF representations so both Pages and browsers accept the paste.

Destinations (Greenshot-style):
- Default: clipboard + default folder (both toggleable).
- Favorites: user-managed list of folders in Preferences, shown in the Save to... menu.
- Save As... (standard panel).
- Open in Preview.

### Editor keyboard shortcuts

V select, C crop, R rectangle, E ellipse, A arrow, L line, T text, N number, H highlighter, B blur, P pen.
Delete removes selection. Cmd+Z / Shift+Cmd+Z undo/redo. Cmd+A selects all. Arrow keys nudge the selection 1 px, Shift+arrow 10 px. Cmd+C copies flattened image. Cmd+S saves to default folder. Cmd+Return Done. Esc deselects, then closes.
Zoom: Cmd+1 actual size (one image pixel per screen pixel), Cmd+9 fit to window, Cmd+plus / Cmd+minus step. Cmd+0 is deliberately NOT a zoom shortcut because it is the global capture hotkey.
Shift constrains shapes to squares/circles and arrows to 45 degree steps.

## Risks and how they are handled

1. **Cmd+0 conflict.** Browsers and editors use Cmd+0 for Actual Size. While ZeroShot runs, that shortcut becomes a screenshot. Preferences lets you change it in 10 seconds.
2. **Screen Recording permission re-prompts.** Caused by unstable code signing across rebuilds. Sign with the Apple Development team from the iOS build recipe, or a fixed ad-hoc identity.
3. **Retina scale mistakes.** Export tests assert 2x output for 2x input.
4. **Text editing in a custom canvas.** Solved with an NSTextView overlay during editing, not by drawing an editable text field ourselves.
5. **Multi-display full screen.** Apple's `-i` picker already handles multiple displays. Non-interactive full-screen capture of every display is a later addition if wanted.

## Out of scope for v1

Scrolling capture, video recording, OCR, cloud upload, sharing sheets, App Store distribution.


Rerun `xcodegen generate` after adding files: `Sources` and `Tests` are folder
groups, so new files are picked up automatically but the project has to be
regenerated.

The app is signed with the Apple Development identity for team G6U69FC9H3 and is
**not sandboxed**, because it runs `/usr/sbin/screencapture` and writes PNGs into
user folders such as ~/Desktop.

On the first capture macOS asks for Screen Recording permission for ZeroShot.
Until it is granted, `CaptureService.capture` returns nil and the app does
nothing, which looks exactly like pressing Esc.

### Release install

`Scripts/build-release.sh` regenerates the project, builds Release into
`build/Release`, quits any running ZeroShot, and copies the app to
`/Applications/ZeroShot.app`. Same stable signing identity as Debug, so a
reinstall does not re-trigger the Screen Recording permission prompt.

`Scripts/make-icon.swift` (run with `swift Scripts/make-icon.swift`) draws
`Resources/AppIcon.icns` from scratch with Core Graphics: no `.xcassets`
catalog in this project. Re-run it and then `xcodegen generate` if the icon
design ever changes.

**xcodegen gotcha**: a target-level `resources:` key is accepted by xcodegen
2.45.3's YAML parser (`xcodegen dump` shows it resolved correctly) but
silently produces no Copy Bundle Resources build phase at all, so nothing
actually lands in the built app's `Contents/Resources`. The fix used here is
adding the resource path under `sources:` instead, with `buildPhase:
resources`. See `project.yml`.
